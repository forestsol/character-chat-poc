# 프로젝트 개요

## 1. 프로젝트명

AI 기반 등장인물 대화 웹 PoC

## 2. 프로젝트 목적

책에서 추출된 텍스트와 이미지를 분석하여 작품의 등장인물, 장소, 물건, 사건, 관계를 구조화하고, 주요 등장인물의 캐릭터 프로필을 생성한다.

사용자는 분석이 완료된 주요 등장인물 중 대화가 허용된 인물과 대화할 수 있다.

이번 PoC는 실제 운영 서비스보다 다음 항목을 검증하는 데 목적이 있다.

- 책의 텍스트와 이미지를 함께 분석할 수 있는가
- 책에 등장하는 고유 인물 후보를 추출할 수 있는가
- 사건과 관계를 KG 형태로 구조화할 수 있는가
- 질문과 관련된 원문을 RAG로 검색할 수 있는가
- 최종 캐릭터 프로필, RAG 근거, KG 관계를 조합해 캐릭터다운 답변을 생성할 수 있는가

## 3. 입력과 출력

### 입력

회사의 기존 스캔 및 OCR 기능이 다음 결과를 제공한다고 가정한다.

- 페이지별 OCR 텍스트
- 페이지 번호와 순서
- 페이지에서 추출된 삽화 이미지
- 이미지가 어느 페이지에서 추출되었는지에 대한 연결 정보

이번 PoC에서는 회사 시스템 대신 사람이 검수한 합성 도서 데이터를 사용한다.

- 앨리스 동화책과 유사한 합성 도서 1권
- 페이지별 텍스트 파일
- 페이지별 이미지 파일
- 책과 페이지의 연결 정보를 담은 메타데이터 파일

### 출력

- 책의 원본 페이지, 문단, 이미지 데이터
- 등장인물, 장소, 물건 등의 개체 후보
- 이미지와 텍스트에서 추출한 장면 정보
- 주요 사건
- KG 개체와 관계
- 검수된 주요 등장인물
- 선택된 등장인물의 결말 시점 최종 프로필
- RAG 검색 결과
- 등장인물의 답변

## 4. 기술 방향

- 백엔드: Java 17, Spring Boot 3.5.x, Gradle 단일 프로젝트, Spring Web MVC, MyBatis, JDBC, Flyway
- 백엔드 기본 지원: PostgreSQL JDBC Driver, Spring Actuator, springdoc-openapi, JUnit 5, Spring Boot Test
- 프론트엔드: Next.js 15, React 19, TypeScript, TanStack Query, Tailwind CSS, Radix UI, lucide-react
- 데이터베이스: PostgreSQL과 pgvector
- 외부 LLM 및 멀티모달 API: 미정
- 임베딩 모델: 미정
- KG 저장 방식: PostgreSQL의 개체 및 관계 테이블
- RAG 저장 방식: PostgreSQL에 원문과 메타데이터를 저장하고 pgvector로 임베딩 저장 및 벡터 유사도 검색

Spring Boot의 정확한 3.5.x patch 버전과 외부 AI API 연동 방식은 프로젝트 생성 및 연동 작업 시점에 결정한다.

## 5. 핵심 구조

```text
책 입력
→ 원본 데이터 저장
→ 텍스트 기반 개체 후보 추출
→ 같은 페이지 텍스트와 개체 후보를 활용한 이미지 분석
→ 텍스트 및 이미지 정보 병합
→ 사건과 관계 추출
→ KG 구축
→ 사람의 등장인물 검수 및 대화 허용 설정
→ 결말 시점 최종 캐릭터 프로필 생성
→ RAG 검색 및 KG 조회
→ 외부 LLM을 통한 캐릭터 답변 생성
→ Next.js 발표 화면
```

## 6. 주요 원칙

- 원본 데이터와 AI 분석 결과를 구분한다.
- RAG는 저장소 자체가 아니라 관련 원문을 찾기 위한 검색 구조다.
- 같은 페이지 텍스트가 필요할 때는 페이지 번호로 직접 조회한다.
- 캐릭터 프로필은 항상 사용하므로 DB에서 직접 조회한다.
- 사용자 질문과 관련된 원문은 RAG에서 검색한다.
- 사용자 질문과 관련된 구조화된 관계는 KG에서 조회한다.
- 텍스트, 이미지, 추론 결과의 출처를 구분한다.
- 알 수 없는 정보는 임의로 생성하지 않고 UNKNOWN으로 남긴다.
