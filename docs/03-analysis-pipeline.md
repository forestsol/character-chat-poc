# 분석 파이프라인

## 1. 파이프라인 개요

```text
표준 책 입력
→ 원본 데이터 저장
→ 텍스트 기반 개체 후보 추출
→ 페이지별 이미지 분석
→ 텍스트 및 이미지 정보 병합
→ 사건과 관계 추출
→ KG 구축
→ 등장인물 검수
→ 최종 캐릭터 프로필 생성
→ RAG 검색
→ 캐릭터 대화
```

RAG 색인은 원문 저장 이후 어느 시점에도 만들 수 있으나, 초기 구현 작업에서는 분석 구조가 안정된 뒤 별도 작업으로 구현한다.

## 2. 단계별 설명

### 단계 1. 표준 책 입력

입력:

- 책 메타데이터
- 페이지별 텍스트
- 페이지별 이미지
- 페이지 순서
- 텍스트와 이미지 연결

출력:

- BookInput

### 단계 2. 원본 데이터 저장

텍스트는 문단 단위로 저장한다.

저장 항목:

- Book
- BookPage
- BookParagraph
- BookImage

주요 원칙:

- 원문을 수정하지 않는다.
- 문단의 페이지 위치와 전체 순서를 보존한다.
- 이미지 파일 자체보다 파일 경로 또는 파일 참조를 저장한다.
- AI 분석 결과와 원본 데이터를 분리한다.

### 단계 3. 텍스트 기반 개체 후보 추출

먼저 관계의 주체와 대상을 확보하기 위해 개체 후보를 추출한다.

초기 추출 대상:

- CHARACTER
- PLACE
- OBJECT
- ORGANIZATION

추출 결과:

- 정규 이름 후보
- 별칭과 지칭 표현
- 간단한 설명
- 근거 pageNumber
- 근거 sourceOrder
- 신뢰도
- 기존 후보와 동일 개체인지 여부

긴 책을 고려한 목표 구조:

```text
부분별 후보 추출
→ 기존 후보 목록과 비교
→ 동일 개체 및 별칭 통합
→ 전체 후보 최종 검증
```

이번 합성 도서가 짧다면 전문 분석을 초기 기준선으로 시험할 수 있지만, 코드 구조는 부분별 분석으로 확장 가능해야 한다.

초기 구현은 문단을 설정 가능한 배치로 나누고, 앞 배치에서 누적한 정규 이름과 별칭을 다음 배치에 전달한다. AI 응답의 근거 `sourceOrder`와 실제 원문 속 지칭 표현을 서버에서 검증한 뒤 `BookParagraph`에 연결한다. 모든 배치가 성공한 경우에만 기존 후보를 새 결과로 교체한다.

### 단계 4. 페이지별 이미지 분석

이미지만으로 앨리스, 흰 토끼 등의 이름을 판단하기 어렵기 때문에 다음 정보를 함께 제공한다.

- 같은 페이지의 텍스트
- 현재까지 추출된 개체 후보
- 이미지 파일

같은 페이지 텍스트는 RAG 검색이 아니라 pageNumber로 직접 조회한다.

추출 대상:

- 이미지 속 기존 인물 후보
- 신규 인물 후보
- 외모
- 옷차림
- 표정
- 행동
- 장소
- 실내 또는 실외
- 눈에 보이는 날씨
- 시간대 후보
- 주요 물건
- 이미지에만 보이는 장면 단서

확실하지 않은 인물 연결은 미확정으로 남긴다.

### 단계 5. 텍스트 및 이미지 정보 병합

텍스트 결과와 이미지 결과를 각각 보존한 뒤 병합한다.

출처 유형:

```text
TEXT
IMAGE
TEXT_AND_IMAGE
INFERRED
```

정보 상태:

```text
CONFIRMED
CANDIDATE
UNKNOWN
CONFLICT
```

이번 테스트 도서는 충돌을 줄이도록 검수하지만, 데이터 구조는 충돌 상태를 표현할 수 있어야 한다.

병합 시 주의사항:

- 한 장면의 표정을 전체 성격으로 확정하지 않는다.
- 한 장면의 옷차림을 고정 외모로 확정하지 않는다.
- 실내 장면에서 보이지 않는 실외 날씨를 추측하지 않는다.
- 이미지에서 관찰된 정보와 AI의 해석을 구분한다.

### 단계 6. 사건과 관계 추출

병합된 정보를 기반으로 주요 사건을 추출한다.

사건 예시:

```text
앨리스가 흰 토끼를 따라감
앨리스가 토끼굴로 떨어짐
앨리스가 모자 장수의 다과회에 참여함
앨리스가 하트 여왕의 재판에 참석함
```

관계 예시:

```text
앨리스 → FOLLOWED → 흰 토끼
흰 토끼 → POSSESSES → 회중시계
앨리스 → MET → 모자 장수
하트 여왕 → HOSTILE_TO → 앨리스
```

각 사건과 관계에는 원문 또는 이미지 근거를 연결한다.

### 단계 7. KG 구축

확정 또는 승인된 개체와 관계를 KG 저장 구조에 반영한다.

KG는 다음 질문에 답하기 위한 구조다.

- 앨리스와 흰 토끼는 어떤 관계인가
- 회중시계는 누구의 물건인가
- 앨리스가 어떤 사건에 참여했는가
- 하트 여왕이 누구에게 명령했는가

초기에는 직접 관계 조회를 우선하며, 복잡한 다단계 그래프 탐색은 제외한다.

KG는 별도 그래프 DB가 아니라 PostgreSQL의 개체 및 관계 테이블에 저장한다.

### 단계 8. 등장인물 검수

AI가 추출한 고유 등장인물 목록과 근거를 화면에 표시한다.

사람이 결정하는 값:

- narrativeRole
- chatEnabled
- 동일 인물 통합 여부
- 별칭 수정
- 잘못 추출된 인물 제거

역할 후보:

```text
MAIN
SUPPORTING
MINOR
UNKNOWN
```

이번 PoC에서는 한 명만 chatEnabled로 설정한다.

### 단계 9. 결말 시점 최종 캐릭터 프로필 생성

선택된 인물에 대해서만 정밀 프로필을 생성한다.

입력:

- 텍스트 원문
- 이미지 관찰 정보
- 주요 사건
- KG 관계
- 검수된 인물 정보

출력:

- 이름과 별칭
- 역할
- 지속적 외모
- 성격
- 가치관
- 목표
- 말투
- 주요 경험
- 다른 인물에 대한 태도
- 결말 시점에 알고 있는 주요 사실
- 원문 및 이미지 근거
- EXPLICIT 또는 INFERRED 구분

프로필은 매 대화에서 항상 필요하므로 DB에서 직접 조회한다.

### 단계 10. 기본 RAG 검색

RAG 문서와 임베딩은 PostgreSQL에 저장하고, 임베딩 저장 및 벡터 유사도 검색에는 pgvector를 사용한다.

초기 기준선:

```text
문단별 임베딩
→ 질문과 유사한 문단 상위 K개 검색
→ 각 검색 문단의 앞뒤 N개 문단 조회
→ 겹치는 범위 병합
→ LLM에 문맥으로 전달
```

초기 설정값은 코드에 고정하지 않고 설정으로 분리한다.

예시:

```text
topK = 3
contextWindow = 2
```

청킹과 검색 전략은 교체 가능한 인터페이스로 분리한다.

### 단계 11. 캐릭터 대화

```text
사용자 질문
→ 대화 캐릭터 프로필 직접 조회
→ RAG 원문 검색
→ 관련 KG 관계 조회
→ 프롬프트 조립
→ 외부 LLM 호출
→ 캐릭터 답변 반환
```

답변 원칙:

- 캐릭터의 1인칭 관점 유지
- 결말 직후 시점 유지
- 작품과 분석 근거에 기반
- 근거가 없으면 모른다고 답변
- 명시되지 않은 감정이나 동기를 확정적으로 생성하지 않음

## 3. 파이프라인 상태

책의 처리 상태는 단계별로 관리할 수 있다.

```text
IMPORTED
TEXT_ENTITIES_EXTRACTED
IMAGES_ANALYZED
MULTIMODAL_MERGED
KG_BUILT
CHARACTERS_REVIEWED
PROFILE_GENERATED
RAG_INDEXED
CHAT_READY
FAILED
```

상태 이름과 세부 전환 방식은 구현 단계에서 확정한다.
